# Unified Offline Verifier Contract v0.1

Status: REFERENCE / DESIGN BOUNDARY
Gate 2: NOT PASSED
Production V4 activation: NOT AUTHORIZED

## Purpose
The unified verifier is an offline, provider-independent verifier for the complete HAHAWEEK-EVIDENCE-V4 evidence artifact set.
It must not mutate production evidence, advance a production cursor, perform migration, or select a provider.

## Required checks
For every positive vector:
- validate fixture schema;
- validate protocol and domain;
- canonicalize according to the frozen protocol;
- compute the domain-separated SHA-256 when the vector is normatively verified;
- compare the expected hash/artifact identity;
- reject malformed or schema-invalid input.

For every negative vector:
- apply the declared mutation;
- verify that the expected integrity/accounting error is produced;
- never silently normalize the mutation back to the positive vector.

## Cross-artifact checks
The verifier must additionally validate, where applicable:
- transition predecessor and sequence continuity;
- reorg observation linkage;
- acquisition coverage and pagination identity;
- segment identity/body/seal consistency;
- manifest segment/acquisition references and cumulative semantics;
- checkpoint references to manifest and evidence watermark;
- cursor authority and next-block derivation;
- lease identity and fencing invariants;
- migration source accounting;
- migration-manifest accounting and self-hash exclusion;
- backup references to manifest/checkpoint inventory.

## Current limitation
Several fixtures intentionally contain UNVERIFIED_NORMATIVE_VECTOR because the current repository reference serializer is JCS-like rather than a complete RFC 8785 implementation, and some historical F-01 vectors use a different hash grammar.
Therefore this contract is not evidence that Gate 2 is passed.

## Promotion rule
A fixture may be promoted from REFERENCE_ONLY to NORMATIVE_VERIFIED only after:
1. canonical bytes are generated by the normative serializer;
2. expected SHA-256/artifact identity is independently reproduced;
3. positive and negative vectors pass;
4. cross-artifact linkage is verified;
5. CI reproduces the result from a clean checkout.

No production V4 cutover is permitted before Gate 2 PASS.
